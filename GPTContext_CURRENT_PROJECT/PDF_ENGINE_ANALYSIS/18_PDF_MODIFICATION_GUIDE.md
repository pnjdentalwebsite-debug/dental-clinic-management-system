# 18 PDF Modification Guide

## Rule

To match a reference PDF, modify React structure and CSS layout. Do not start by changing `jsPDF` coordinates because current PDFs are screenshots of DOM, not native PDF text/shape instructions.

## Global Files To Modify

| Goal | Files |
|---|---|
| Change export quality/page size | `capturePrintableDocument.ts`, `PDFDesignerPage.tsx`, `PatientFormsWorkspace.tsx` |
| Change A4 visual dimensions | `src/index.css`, capture helper |
| Change header | `ConfigurableDocumentHeader.tsx`, `modifyPdfSettings.ts`, `src/index.css` |
| Change settings controls | `PDFDesignerPage.tsx`, `modifyPdfSettings.ts` |
| Change patient-side output | `PatientFormsWorkspace.tsx`, print form component |

## Patient Form Modification

Current implementation:

- grid-based form sections
- fixed 680x962 page
- section visibility/order from settings
- underlines via `i` elements

Required modification path:

1. Edit JSX sections in `PatientRecordPrintForm.tsx`.
2. Edit row grids in `.patient-print-form__row-*`.
3. Edit field styles in `.patient-print-form__field`.
4. Adjust `patientFormSections` if new sections must be configurable.

Expected output:

- fields align to target reference rows
- labels and values preserve patient data binding
- signature/footer remains inside page

## Dental Chart Modification

Current implementation:

- tooth arrays define order
- `ToothArch` splits teeth into left/right halves
- SVG surfaces draw conditions
- CSS grid controls spacing

Required modification path:

1. Edit tooth arrays if numbering/order differs.
2. Edit `ToothArch` or `PrintTooth` if tooth rendering differs.
3. Edit `.dental-chart-print__chart-body` and `.dental-chart-print__arch`.
4. Edit legend arrays and `.dental-chart-print__legend`.

Expected output:

- tooth chart matches reference positioning
- labels and center line align
- condition marks remain driven by dental chart data

## Treatment Record Modification

Current implementation:

- fixed HTML table
- 32 rows
- dynamic dentist/balance columns
- row density class

Required modification path:

1. Edit `blankRows` for row count.
2. Edit colgroup classes for column widths.
3. Edit table header JSX for labels/order.
4. Edit cell height and padding CSS.

Expected output:

- table dimensions and rows match target reference
- data mapping still fills row cells by index

## Certificate Form Modification

Current implementation:

- compact header
- static contact block
- body paragraphs with inline blanks
- writing lines generated by `WritingLines`

Required modification path:

1. Edit certificate paragraphs in JSX.
2. Edit `WritingLines count`.
3. Edit `.certificate-print-form h1`, body, inline, and dentist styles.

Expected output:

- certificate typography and spacing match reference
- patient/dentist values remain prop-driven

## Consent Form Modification

Current implementation:

- medical checklist columns from arrays
- allergy checklist
- risk list from static array
- signatures bottom-aligned

Required modification path:

1. Edit `medicalColumns`, `allergyItems`, or `risks`.
2. Edit `ChecklistColumn` for checkbox logic/shape.
3. Edit medical grid CSS for column width.
4. Edit signature grid CSS.

Expected output:

- checklist and paragraphs wrap like reference
- yes/no marks remain data-driven

## Contract Form Modification

Current implementation:

- four manual pages
- static legal arrays
- payment table on page 4

Required modification path:

1. Move content between `data-pdf-page` sections for page breaks.
2. Edit static arrays for legal text.
3. Edit `.contract-print-form__page` spacing.
4. Edit ledger table JSX/CSS for payment table.

Expected output:

- pages break exactly as target PDF
- long text remains readable and does not overflow

## Engine Modification Warning

Only modify `capturePrintableDocument` if the target requires different output resolution or page dimensions. Most visual mismatches are CSS/JSX problems, not PDF engine problems.
